## Выбранная архитектура

Облачное хранилище онлайн школы (платформы) веб версия.
(допустим ранее использоали гугл самую простую подписку, а яндекс и мэил ру запрещены политикой компании)
## 0. Контекст:
1. Система позволяет загружать,хранить,скачивать,удалять, искать файлы в рамках персонального облачного хранилища с возможностью онлайн просмотра, создания вложенной структуры директорий и ограничением доступ и права к файлам.
Допустимые форматы для онлайн просмотра: txt,docx,rtf,pdf,xslx,csv,png,jpeg,pptx. 
Допустимые форматы для комментирования: txt,docx,rtf,xslx,csv.
Доступные форматы для редактирования: txt,docx,rtf.
Файл/директория доступен по сформированной ссылке либо по предоставленному персональному доступу.
Допустимые к выбору права доступа: читатель, комментатор, редактор.
Аутентификация происходит посредством интеграции с платформой школы.
Материалы урока доступны студентам (роль читатель), преподавателям (редактор).
Для ДЗ у студента есть отдельная директория (роль редактор), преподаватели (комментатор).
Администратор редактор во всех директориях курса.
2. Акторы:
студенты (загрузка файлов ДЗ, удаление, редактирование онлайн, поиск файлов, чтение по предоставленному доступу к файлу урока, скачивание их, онлайн просмотр файлов урока, формировать ссылку на просмотр)
преподаватели (загрузка материалов урока, удаление, редактирование онлайн, чтение по предоставленному доступу файлов ДЗ и комментирование их, формировать ссылку на просмотр)
администраторы онлайн школы (создание вложенной структуры директорий,упраление правами доступа к директирориям, создание удаление скачивание, шеринг доступа и ссылок)
3. Загрузка файла - скачивание файла - формирование ссылки - отзыв прав у пользователя - комментирование файла
4. Объем 1 файла не более 500Мб. Объем бесплатного хранения 5 Гб.
География РФ
   Редактирование одновременно несколькими пользователями не подразумевается.
Время отображения превью файла до 1с 
Время скачивания файла до 1 Мб - до 1.5 с до 4 при скачивании по сети Wifi, оптоволокно.
Время скачивания файла до 50 мб - до 4 при скачивании по сети Wifi, оптоволокно.
RPS в штатном режиме - 500 чтение просмотр, скачивание/загрузка - 100
RPS в режиме повышенной нагрузки - 5000 чтение просмотр, скачивание/загрузка - скачивание/загрузка - 500 


## 1. Компоненты


| Компонент                              | Stateless | Ответственнсть                                                                                                                                                                 |

| AuthPlatform (платформа обучения)      |           | (внешняя) принимает запрос от веб морды хранилища на аутентификацию пользователя от GW, формирует данные о сессии                                                              |

| DB Redis                               |           | хранит ссылки долгие (кэш), данные о сессии пользователя (самостоятельная БД) и актуальных правах (кэш)                                                                        |
| SDN                                    |           | хранит кэш с файлами                                                                                                                                                           |
| Kafka                                  |           | принимает события изменений по файлам, уведомления                                                                                                                             |


## 2. Потоки данных

_3–5 ключевых сценариев со схемами._
1. Загрузка файла (с проверкой сессии)
   <br/>1 проверка и сессии и прав
   <br/>2 запить первых данных в БД
   <br/>3 генерация ссылки на загрузку и отправка в браузер
   <br/>4 генерация превью сервисом Thumbnail
   <br/>5 уведомление о завершении и отправка полных метаданных в БД
```mermaid
flowchart TD
 Client_Web -->|HTTPS| API[API GW]
    API --> FileEng[FileEng]
    FileEng --> |1 grpc| PersonEng[PersonEng]
    PersonEng --> DB2[(Redis)]
    PersonEng --> FileEng
    FileEng --> |2| DB[(PostgreSQL)]
    DB --> FileEng
    FileEng --> |3| Storage@{ shape: lin-cyl, label: "MinlO" }
    Storage --> FileEng
    FileEng --> API
    API --> |3| Client_Web
    Client_Web --> |asinc| Storage
    Storage --> |asinc| EventBus[Kafka]
    EventBus --> |4| Thumbnail[Thumbnail]
    EventBus --> |5| Notify[Notify]
    Thumbnail --> Storage
    EventBus --> |5| FileEng
    Storage --> CDN@{ shape: das, label: "CDN" }
  
```
2. Скачать файл (при условии что сессия активна)
   <br/>1 запросить права на скачку по пользователю
   <br/>2 проверить в БД есть ли файл
   <br/>3 получить ссылку на скачивание по идентификатору из бд сформировать ссылку и отдать клиенту
   <br/>4 отправить уведомление о завершении скачивания
```mermaid
   flowchart TD
   Client_Web -->|HTTPS| API[API GW]
   API --> FileEng[FileEng]
   FileEng --> |1 grpc| ShareEng[ShareEng]
   ShareEng[ShareEng] --> DB2[(Redis)]
   DB2[(Redis)] --> ShareEng
   ShareEng --> FileEng
   FileEng --> |2| DB[(PostgreSQL)]
   DB --> FileEng
   FileEng --> |3| Storage@{ shape: lin-cyl, label: "MinlO" }
   Storage --> FileEng
   FileEng --> API
   API --> |3| Client_Web
   Client_Web --> |asinc| Storage
   FileEng --> |asinc 3| EventBus[Kafka]
   EventBus --> |4| Notify[Notify]
   Storage --> CDN@{ shape: das, label: "CDN" }
```

3. Поделиться ссылкой на файл с правами на редактирование (админ) (сессия активна) 
<br/>1 запросить права на файл по пользователю (актор)
<br/>2 сформировать ссылку на файл в ShareEng,назначить ее пользователю, выдать права редактора и положить в БД
<br/>3 положить в БД Postgres и далее закешировать в БД Redis
```mermaid

   API --> FileEng[FileEng]

   ShareEng --> |1| DB2[(Redis)]

   FileEng --> | 2 grpc| ShareEng
   ShareEng --> |2| DB[(PostgreSQL)]
   ShareEng --> |2 grpc| FileEng
   ShareEng --> |2| DB2
   FileEng --> API
   API --> |3| Client_Web

```



## 3. Проблемы и решения

(реплики и георезервирование и сдн) то ACTIVE-PASSIVE REGIONS

| Компонент                              | Обоснование                                                                                                                                                                                                                  |
|----------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| API GW                                 | проктирование запросов, снимает излишнюю нагрузку на основной бэк и берет часть валидации, маршрутизирует                                                                                                                    |
| Service FileEng                        | нужно больше ресурсов чем остальным сервисам, принимает запросы по изменению состояния файлов и ссылок на них, <br/> считает хэш, пишет в БД метаданные, отправляет в storage, <br/> формирует событие в кафку об изменениях |
| Service Notify                         | потребляет события из кафки и формирует отправку уведомления через smpt сервер                                                                                                                                               |
| Service PersonalEng                    | принимает запрос на проверку пользовалеля, формирует gwt токен сесии, пишет в редис данные по сессии, создание новых пользователей                                                                                           |
| Service ShareEng                       | принимает запросы фиксацию разрешений пользователя на папки, прав на файлы, формирование ссылок на поделиться с учетом прав, отправляет в редис                                                                              |
| Thumbnail                              | получает события от minlO и сжимает файлы для превью                                                                                                                                                                         |
| DB Service FileEng (Metadata) Postgres | нужно хранить связь между пользователем файлами , стукруру и проверять при запросах наличие связей, здесь должно работать шардирование от опредеденных объемов записей по пользователю                                       |
| DB Service PersonalEng Postgres        | аналогично                                                                                                                                                                                                                   |
| Storage MinlO                          | возможности позволяют скачивать напрямую и разгружать бэк, восстанавливать данные из распределенных реплик, закрытый контур без облака, нужно резервирование по региону                                                      |
| DB Redis                               | возможность задать скор жизни сессии и ее прекращение, скорость чтения выше, но кэш может быть неактуальным поэтому первая запись долгая + паралельная запить в кэш                                                          |
| SDN                                    | хранит кэш с файлами, быстрый доступ по регионам                                                                                                                                                                             |
| Kafka                                  | уведомления если нужно отправить 1000+ пользователям по предоставлению прав, синзронный тракт ляжет или будет тормозить                                                                                                      |



## 4. Вопросы к авторам архитектуры

<br/>Не является ли FileEng узким местом, он выполняет роль по сути оркестратора. Но и API GW роль оркестратора выполнять не может.
<br/>Можно ли один инстанс Redis BD использовать как кэш и как самостоятельную БД? 
Если в нее будет писать 2 сервиса сразу, то из-за отказа БД выпадет сразу 2 сервиса.
<br/>Что будет если ссылка протухнет временная при скачивании большого файла, скачивание закончится?
<br/>А если загрузка прервется из-за сети или сервис сдохнет а скачано только 10% было, скачевание начнется заново при восстановлении?
<br/>Если из строя вышел дата центр основной, данные есть только в репликах и сдн, как организовать сбор данных и миграцию в новый ДЦ?
<br/>Если файл был создан в одном регионе, выданы на него права редактировная польователю из другого региона, первым пользователем он был изменен, а пользователь 2 уже начал редавтировать этот файл. Что будет?
